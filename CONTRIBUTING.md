# Contributing

## Setting up

```bash
npm install   # installs dependencies and activates the Husky hooks
npm run dev
```

## Before opening a PR

```bash
npm run format:check && npm run lint && npm run typecheck && npm test
```

The `pre-commit` hook runs ESLint and Prettier on staged files.

## Commit messages

We use [Conventional Commits](https://www.conventionalcommits.org): `type(optional scope): description`.

| Type                                                        | Version effect |
| ----------------------------------------------------------- | -------------- |
| `feat`                                                      | minor          |
| `fix`, `perf`                                               | patch          |
| `feat!` / `BREAKING CHANGE:` in the body                    | major          |
| `docs`, `style`, `refactor`, `test`, `build`, `ci`, `chore` | no release     |

Examples:

```
feat(queue): animate reroll
fix(timer): keep overtime counting after expire
docs: explain release flow
```

Make small commits grouped by feature. Versions and `CHANGELOG.md` are generated by semantic-release; don't edit them by hand.

## Code conventions

- Components are organised by _atomic design_ (`atoms` → `molecules` → `organisms`), each in its own folder with its `.module.css` and, where relevant, its test.
- Domain logic lives in `features/`, browser effects in `services/` and pure functions in `utils/`.
- Prefer pure functions and small hooks with a single responsibility; test them next to the code (`*.test.ts[x]`).
